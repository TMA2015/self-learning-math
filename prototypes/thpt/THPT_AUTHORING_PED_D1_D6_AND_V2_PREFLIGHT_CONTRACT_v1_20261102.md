## B. No-repeat execution order (mandatory for G12 / future SGK)

1. **S1 FIRST:** read the owner-provided original SGK + SBT in *correct volume*; record authoritative printed-page ranges and excluded enrichment/experiential topics. The exact book/scope and original PDF or cited source receipt is mandatory. If a page conflicts, mark `SOURCE_RECEIPT_CONFLICT` and reconcile with S1 before claiming A2.
2. **OUTCOME MAP BEFORE CONTENT:** one stable `skill_id=outcome_id` per expected outcome; explicit Bài → outcome → D1 intuition/conditions → D2 why-based example → D3 Core/Practice/Application → D4 Written/rubric → D5 SVG and reading instructions → D6 remediation → private RD1 purpose. Integrated outcomes get **visible knowledge/skill evidence**, but need not have a cloned public MCQ.
3. **PED BEFORE FORMULAS:** for each lesson, the narrative must start from a problem requiring a new concept. Explain prerequisite vocabulary, build meaning geometrically/numerically, then formalize with all mathematical conditions. Explain which method solves which task, include anti-example, explicit worked D2 reasoning and an ungraded first try **before Core** with actual remediation path. A lesson with D1 definitions as its first instructional content fails author preflight even if S1 coverage seems full.
4. **DETERMINISTIC ID CUSTODY:** one question—one canonical item ID, no duplicate between chapters/paths. D3/D4 metadata includes role, placement, outcome, answer/solution and rubric where appropriate. Anchor is a tag of Written, not an additional item. Keep source record apart from private RD1 and independent assessment evidence. Never count mere practice correctness as mastery.
5. **AUTHOR SOURCE LOCK:** write ONE canonical Markdown at `content-drafts/` **before** review; verify Git blob SHA, original file title and item register. If assembled from components, ensure the review packet includes *the full combined source* and maps every component/ID. A text export with normalization changes requires equivalence evidence; do not claim hash equality without bytes.
6. **RUN STRUCTURAL PREFLIGHT:** execute `node scripts/audit-thpt-authoring-preflight.cjs <public-source.md> --lesson-nums=... --items=... --outcomes=... --sha=... --require-ped`. Structural PASS only locates issues; it does **not** certify math, diagrams, semantic coverage or pedagogy. Fix any duplication/ID and structural BLOCKER before sending for external review.
7. **ONE CHAPTER REVIEW:** prepare an actual `Temp_*.md`/txt plus short prompt, 5 Permanent THPT Sources v2.0, original S1 books, full D1–D6 and protected private review source in NotebookLM, expected ID list and P0/P1/P2/minimal delta. Per file 1–2 links; ≥3 Temp files → one Temp ZIP and explicit unzip instruction. **Do not send JSON as NotebookLM review input.**
8. **IND. ACADEMIC + PED VERDICTS:** require both separately, per lesson/outcome/item and source receipt, canonical/alias identity and private coverage. Source text being grammatically polished ≠ independently reviewed. Missing/ambiguous receipt means HOLD; if only PED fragment changed, do targeted Delta_C not whole chapter.
9. **SINGLE EFFECTIVE A6 HANDOFF V2:** after all A1–A7/PED source gates independently pass, one `release-handoffs/` manifest, one ready packet matching REGISTER and exact Git source+review blobs. Preflight the V2 source-lock CI; no duplicate READY manifests for overlapping scope. If any academic blocker remains, `BLOCKED_BY_AUTHORING` with exact Bài/outcome/item, not `CONTENT_READY` by summary text.
10. **STOP AT AUTHORING:** A6 release independently verifies AP1–AP5, actual rendering, Final Submit, RD1 exposure model, links, Golden UI/THCS regression, exact-head CI, owner authorization/PAUSE, P1/P2. An author source or NotebookLM PASS does not authorize merge/deploy, activate official readiness or Mastery.
